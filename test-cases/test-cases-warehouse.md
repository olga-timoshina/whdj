# TC-011 — Проверка DOM-элемента ошибки при невалидном вводе (Elements)

| Поле | Значение |
|---|---|

| **Дата создания** | 2026-11-16 |
| **Окружение** | Chrome 130+, Windows 11, DevTools → Elements |

## 🎯 Цель
Проверить, что при невалидном вводе в форме создания товара в DOM появляется элемент ошибки, связанный с полем (для доступности и автотестов).

## ✅ Предусловия
- Сайт открыт
- Открыт DevTools (F12) → вкладка Elements
- Пользователь на форме создания товара («Товары» → «Добавить»)

## 🧪 Тестовые данные

| Поле | Значение |
|---|---|
| Наименование | `(пусто)` |
| Цена | `abc` |

## 📋 Шаги выполнения

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть форму создания товара | Форма отображается |
| 2 | Оставить «Наименование» пустым, нажать «Сохранить» | Появляется сообщение об ошибке (визуально) |
| 3 | В DevTools → Elements найти элемент ошибки | В DOM присутствует элемент с классом `error`, `invalid-feedback` или `is-invalid` |
| 4 | Проверить связь элемента ошибки с полем | У поля есть атрибут `aria-describedby`, указывающий на ID элемента ошибки (или аналогичная связь) |
| 5 | Ввести `abc` в поле «Цена», нажать «Сохранить» | Появляется ошибка валидации; в DOM — соответствующий элемент ошибки рядом с полем «Цена» |

# TC-012 — Консистентность стилей: шрифты и отступы

| **Дата создания** | 2026-11-16 |
| **Окружение** | Chrome 130+, Windows 11, разрешение 1440×900 |

## 🎯 Цель
Убедиться, что на всех страницах системы используются единые шрифты, размеры, цвета и отступы — интерфейс выглядит целостно.

## ✅ Предусловия
- Сайт открыт
- Доступны разделы: Главная, Товары, Склады, Контрагенты, Документы

## 📋 Шаги выполнения

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть главную страницу, зафиксировать шрифт и размер заголовка (через DevTools → Computed) | Заголовок: единый шрифт, размер, цвет |
| 2 | Перейти в «Товары», сравнить заголовок и шрифт основного текста с главной | Шрифт, размер, цвет совпадают с главной |

| 6 | Проверить, что нет «выбивающихся» элементов (другой шрифт, другой цвет кнопки) | Все элементы соответствуют единому стилю |

## 🎯 Цель
Проверить, что все кнопки навигации и формы реагируют на клик, выполняют заявленное действие, а кнопка «Сохранить» блокируется при невалидных данных; «Отмена» закрывает форму без сохранения.

| 7 | Проверить кнопку «Удалить» (если есть) у созданной записи | Кнопка активна; при клике — подтверждение удаления (или удаление с уведомлением) |
